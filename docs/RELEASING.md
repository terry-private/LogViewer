# 公開手順

この文書は各バージョンで再利用する手順であり、今回の進捗はGitHub Issueと
リリースPull Requestで管理する。

## 公開前ゲート

- [ ] 公開対象commitでXcode 26安定版の`./Scripts/verify.sh`が成功している
- [ ] `./Scripts/verify-docs.sh`と`./Scripts/verify-sample.sh`が成功している
- [ ] 実端末手動チェックを完了し、端末、OS、言語、文字サイズをPRへ記録している
- [ ] 公開API、README、DocC、MIGRATIONが一致している
- [ ] `CHANGELOG.md`の対象版から「未公開」を外し、公開日を設定している
- [ ] 依存パッケージのライセンスと最低バージョンを確認している
- [ ] 重大・中程度のレビュー指摘がなく、CIが成功している

## 1.0.0以後のAPI互換性確認

既存タグに対する破壊的変更を診断する。

```bash
swift package diagnose-api-breaking-changes <直前の安定版タグ>
```

診断結果が意図したメジャー更新以外の破壊的変更を含む場合は公開を中止する。
1.0.0は最初の基準タグとなるため、公開APIテストとレビューで公開面を確定する。

## タグとGitHub Release

1. 公開対象commitが既定ブランチへ取り込まれていることを確認する
2. 署名付きまたは注釈付きタグ`<major>.<minor>.<patch>`を同じcommitへ作成する
3. タグをpushし、タグ指定の空の利用アプリで`LogViewer`、`LogViewerCore`、
   `LogViewerSwiftLog`の製品解決とビルドを確認する
4. `CHANGELOG.md`の対象見出しを要約したGitHub Releaseを公開し、正本へリンクする
5. 公開URLからのSwift Package解決をもう一度確認する

タグ、Release、公開先への書き込みは、リリース担当者の明示的な承認後に行う。

## 実端末手動チェック

- 物理シェイクで振った場面だけにLogViewerが表示され、連続シェイクで閉じない
- アプリ側のシェイク通知カウンタも増え、独自処理を妨げない
- 2つのiPad場面で表示先、検索、キー状態が独立する
- 日本語・英語の最大文字サイズで重要操作が隠れない
- VoiceOverだけで表示、検索、停止・再開、削除確認、終了まで操作できる
- 現在の絞り込み結果だけがコピー、テキスト、JSONへ共有され、秘密値がない
- 外部共有先でテキストを読め、JSONファイルを開いて配列として復号できる

## 中止条件

- 最低対応環境の検証失敗
- 公開APIと文書の不一致
- 秘密値を含むサンプルまたは書き出し
- 重大・中程度の未解決レビュー指摘
- 公開対象commitと検証したcommitの不一致

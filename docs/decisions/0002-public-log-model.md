# 公開ログモデル

## 背景

従来のログ型はパッケージ内部だけで利用でき、本文、タグ、ファイル、関数、
記録日時しか表現できなかった。ログ接続部品、絞り込み、秘匿化、書き出しを
追加するには、画面機能に依存しない安定した公開モデルが必要である。

## 決定

`LogViewerCore`に次の公開値型を置く。

- `LogEntry`: 1件のログ
- `LogLevel`: 追跡から重大な失敗までのログ水準
- `SourceLocation`: ファイル、関数、行番号

`LogEntry`はUUIDによる識別子、ログ水準、本文、発生元、任意の分類、
重複を除いた順序付きタグ、文字列の付加情報、記録日時を持つ。
値型は`Sendable`、`Hashable`、`Codable`に適合する。

既存の`Logger.shared.add`は維持し、受け取った文字列とタグを`LogEntry`へ
変換する。新しい連携処理は`LogEntry`を直接追加できる。

## 採用理由

- 中核、画面、ログ接続部品で同じ値を共有できる
- UUIDと記録日時により、安定した識別と決定的な並び替えができる
- 文字列の付加情報は`Sendable`と符号化を保ちやすい
- 既存のログ追加コードを変更せず段階的に移行できる

## 採用しなかった方式

- `OrderedSet`を公開プロパティに使う方式:
  外部パッケージの型を公開APIへ露出するため採用しない。
- 任意の`Sendable`値を付加情報に持つ方式:
  等価性、符号化、書き出し仕様が不安定になるため採用しない。
- 既存`Logger`を同時に削除または非推奨化する方式:
  置き換えとなる保存機能と依存性注入が未実装のため採用しない。

## 影響

- 公開APIとして`LogEntry`、`LogLevel`、`SourceLocation`が追加される
- タグは最初の出現順を保ち、重複を除去する
- 同じ記録日時のログはUUID文字列表現で安定して並び替える
- 既存の文字列追加はログ水準`.info`へ変換される
- 共有ロガーの置き換えとスレッド安全性は後続課題で扱う

# 場面単位の専用ウインドウ表示

## 背景

View階層内の`overlay`は、アプリが表示しているシート、全画面表示、警告より
背面になる場合がある。アプリ全体から任意のキーウインドウを探す方式では、
複数の`UIWindowScene`を持つアプリで別の場面へ表示する危険がある。

## 決定

既存互換の`.overlay`に加え、`LogViewerPresentationStyle.window`を提供する。
`.window`では修飾したSwiftUI Viewの背面へ小さな`UIViewRepresentable`を置き、
そのViewの`windowScene`を表示先として使う。

場面ごとのレジストリは同じ`UIWindowScene`に専用ウインドウを1つだけ許可する。
専用ウインドウは通常のシートや警告より上のレベルでキーウインドウになり、
`UIHostingController`で`LogView`を表示する。これにより検索欄がキーボード入力を
受け取れる。

表示前のキーウインドウを弱参照で保存し、閉じるとそのウインドウへキー状態を
戻す。表示ウインドウのルート画面は閉じる際に外し、閉じる処理のクロージャーは
表示管理オブジェクトを弱参照して保持循環を避ける。

## 採用理由

- シートや全画面表示の階層に依存せず最前面へ表示できる
- 呼び出し元Viewから場面を得るため、複数場面で表示先が決定的になる
- 専用ウインドウをキーにすることで検索欄の入力を維持できる
- `.overlay`を標準のまま残し、既存アプリの挙動を変更しない

## 採用しなかった方式

- `UIApplication.shared.connectedScenes`から先頭の場面を選ぶ方式:
  呼び出し元とは別の場面を選ぶ可能性があるため採用しない。
- 常に`.sheet`または`.fullScreenCover`を使う方式:
  利用側のモーダル表示と競合するため採用しない。
- 専用ウインドウをキーにしない方式:
  検索欄へキーボード入力できないため採用しない。

## 影響

- 既存コードは標準の`.overlay`表示を継続する
- 最前面表示が必要な利用側だけ`.window`を選択する
- シェイク通知を場面単位へ限定する作業はGitHub課題第11号で扱う
- Swift Packageの単体テストには接続済み`UIWindowScene`がないため、Sceneを
  使うシート前面表示と実キーボード入力のE2E検証はサンプルアプリを扱う
  GitHub課題第15号で追加する

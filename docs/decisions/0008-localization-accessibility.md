# 画面の多言語化とアクセシビリティ

## 背景

ログ画面には日本語と英語の固定文字列が直接記述され、アイコンだけの操作にも
読み上げラベルがなかった。ヘッダーは横一列に固定され、最大文字サイズでは
閉じる、表示方法、操作メニューが競合する。タグとログ水準の選択は主に色へ
依存し、空状態、記録停止、削除前の確認も明示されていなかった。

## 決定

`LogViewerUI`ターゲットへSwift Packageの文字列カタログを置き、日本語と英語を
同じキーで管理する。画面はパッケージのresource bundleから現在の地域設定に
合う文字列を取得する。ログ日時も地域別の`DateFormatter`を共有して表示する。

アイコンだけのボタンへVoiceOverラベルを付け、ログ画面の表示後は閉じる操作へ
アクセシビリティの焦点を移す。選択チップは色に加えてチェック印と`isSelected`
特性を持つ。展開状態、空状態、絞り込み結果なし、記録停止を読み上げ可能な
文字列として表示し、全削除は確認画面を経由する。

アクセシビリティ文字サイズでは、横一列のヘッダーを操作行と表示方法メニューへ
分割する。絞り込み下部の操作は`ViewThatFits`で横配置から縦配置へ切り替える。
ログ本文と発生元は複数行を許可し、重要操作を固定幅へ押し込まない。

## 採用理由

- 文字列カタログを日英の唯一の情報源にできる
- Swift Package単体でも両言語の欠落を自動テストできる
- 視覚、読み上げ、文字サイズのいずれでも同じ操作と状態を把握できる
- 破壊的な削除を利用者の明示確認後だけ実行できる

## 採用しなかった方式

- 固定文字列をViewごとに日英分岐する方式:
  翻訳の欠落と表記揺れを自動検出しにくい。
- アイコンのSF Symbols名を読み上げへ任せる方式:
  操作の目的ではなく図形名として読み上げられる可能性がある。
- 最大文字サイズでも横一列を維持する方式:
  重要操作が縮小・省略・画面外表示になる可能性がある。
- 色だけで選択状態を示す方式:
  色覚や読み上げ環境によって状態を判別できない。

## 影響

- 固定文字列と日時は日本語・英語の地域設定へ追従する
- アクセシビリティ文字サイズではヘッダーの配置が変わる
- 全ログ削除には確認操作が必要になる
- 実際のVoiceOver操作、最大文字サイズでの日英レイアウトは、サンプルアプリを
  扱う[GitHub課題第15号](https://github.com/terry-private/LogViewer/issues/15)の
  アプリホストE2Eで最終確認する

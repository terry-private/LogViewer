# 組み合わせ可能なログ絞り込み

## 背景

従来の`LogFilter`は、すべて、文字列検索、タグ絞り込みのいずれか1つを選ぶ
列挙型だった。検索しながらタグを指定できず、ログ水準と記録日時も条件に
できなかった。空のタグ集合が「タグなしのログだけ」を意味するため、条件を
解除したつもりで結果が狭まる問題もあった。

## 決定

`LogFilter`を、検索文字列、ログ水準集合、タグ集合、タグの一致方法、相対期間を
同時に保持する値型とする。異なる項目はANDで評価し、タグ集合だけはORまたは
ANDを明示的に選択する。空の文字列、ログ水準集合、タグ集合と「すべての期間」
は、それぞれ条件なしとして扱う。

文字列は前後の空白と改行を除き、現在の地域設定を使って大文字小文字と
ダイアクリティカルマークを区別せず、メッセージ、ファイル、関数へ照合する。
画面の検索入力は250ミリ秒待ってから反映し、連続入力中の全件再評価を抑える。

直近5分、1時間、24時間は固定した開始日時ではなく、評価時の現在日時を基準に
する。保存Snapshotか条件が変化した時に加え、相対期間の選択中は次のログが
期間境界を越える表示更新時刻まで待機し、その時だけ再評価する。更新粒度は
直近5分が1秒、直近1時間が10秒、直近24時間が60秒で、同じ区間の境界は1回へ
まとめる。ログ追加や条件変更時は待機予定も作り直す。現在日時より未来のログは
相対期間へ含めず、その記録日時を含む更新区間で再評価する。絞り込みと次回境界の
算出はSnapshotの同じ1回の走査で行う。

表示用の絞り込み済みログ、ファイル・関数グループ、結果件数は、保存Snapshotか
条件が変化した時に一度だけ再構築する。選択肢として表示するタグは未絞り込みの
Snapshotから収集し、条件を追加しても他の選択肢が消えないようにする。

## 採用理由

- 条件の追加時に列挙型の組み合わせを増やさずに済む
- 空の選択を一貫して「条件なし」と解釈できる
- タグのOR／AND仕様が型と画面の両方で明示される
- 絞り込み後のグループと件数を同じキャッシュから導出できる

## 採用しなかった方式

- 条件の全組み合わせを列挙型へ追加する方式:
  条件追加のたびに組み合わせが増え、画面と評価処理の分岐が複雑になる。
- 空のタグ集合を「タグなし」と解釈する方式:
  未選択と区別できず、解除操作の結果が利用者の期待とずれる。
- SwiftUIの描画ごとに全ログを評価する方式:
  ログ件数と画面更新回数に比例して同じ処理を繰り返す。

## 影響

- 画面上の絞り込み操作は、他の条件を維持したまま追加・解除される
- タグ未選択時の挙動は「タグなしのみ」から「タグ条件なし」へ変わる
- `LogFilter`はpackage内の型であり、公開APIの互換性には影響しない
